TECHNICAL REPORT · MILESTONE 1

Autonomous Humanoid Robot Simulation

Chat-controlled & autonomous navigation of the Galaxea R1 in a digital-twin ARENA2036 shopfloor, built in NVIDIA Isaac Sim
Platform: NVIDIA Isaac Sim 5.1 · Isaac Lab · Windows 11 · RTX 5070 Ti (Blackwell)  |  Date: 10 July 2026

1. Executive Summary

This milestone delivers an end-to-end, physics-based simulation of the Galaxea R1 — a wheeled, dual-arm humanoid mobile manipulator — operating inside a digital twin of the ARENA2036 shopfloor reconstructed from industrial CAD data. The robot is driven through a natural-language chat interface and can also perform autonomous point-to-goal navigation. The entire system runs locally on a single consumer GPU.

Concretely, the following capabilities were designed, implemented, and verified:

  • Digital twin: a 129 m × 46 m factory floor and a KUKA robotic cell imported from STEP CAD; the Galaxea R1 imported from URDF; all composed into one metric-accurate USD scene.
  • Language teleoperation: a browser chat UI that turns text (“drive forward”, “wave”, “zoom in”) into live robot and camera commands.
  • Autonomous navigation: R1 self-drives to a goal marker and stops on arrival — reaching targets in any direction despite a ±90° steering limit.
  • Safety & robustness: a physical collider fence confining the robot to its cell, a software runaway-stop, and a one-command “stand up” self-recovery.
  • An auto-following camera so the operator never has to fight the 3-D viewport.

2. System Architecture

The system is a two-process design communicating through a shared JSON command file. This decouples the (lightweight) user interface from the (GPU-heavy) simulator and keeps the control contract explicit.

  ┌──────────────────────────────┐        ┌───────────────────────────────────┐
  │  CHAT UI  (Gradio, browser)  │  JSON  │  ISAAC SIM  (r1_chat_sim.py)      │
  │  http://127.0.0.1:7860        │ ─────▶ │  • R1 articulation (26 DoF)       │
  │  text → {vx, turn, arm,       │ r1_cmd │  • PhysX physics + cell fence     │
  │  cam, stand, nav} command      │ .json  │  • follow-camera + goal marker    │
  └──────────────────────────────┘        │  • teleop + autonomous nav loop   │
                                            └───────────────────────────────────┘

The simulator reads the command file every physics frame and applies it to the robot; the UI writes the file whenever the user issues a command. Because the contract is a plain JSON document, the language layer can later be swapped for a large-language-model planner without touching the simulator.

4. Building the Digital Twin

4.1 The Galaxea R1 robot

R1 is a three-wheel steering (“vector”) mobile base carrying two 6-DoF arms, a 4-DoF torso, and grippers — 1.73 m tall, 26 actuated joints. It was imported from the manufacturer’s open URDF and converted to USD with Isaac Lab’s URDF importer. The URDF referenced its meshes with ROS package:// paths that the importer could not resolve; these were rewritten to absolute file paths, after which all 34 collision/visual meshes (~89 MB) imported cleanly.

4.2 The shopfloor & KUKA cell (CAD → USD)

The environment was supplied as STEP CAD files (a 129 m factory hall and a KUKA robotic cell). Isaac Sim’s general asset converter rejected STEP; the correct path is the HOOPS Core CAD converter, invoked directly. All three STEP files tessellated to USD successfully:

Source (STEP)Output (USD)Measured size

4.3 Scene composition

Inspection confirmed all assets shared metric units and a common CAD frame — the KUKA was already positioned inside the shopfloor coordinate system. The three assets were referenced into a single stage, lifted so the floor sits at z = 0, lit, and R1 placed beside the KUKA. A follow-camera was authored to frame the working area automatically.

5. Milestone 1 — Control & Autonomy

5.1 Language teleoperation

A rule-based parser maps free text to a persistent command state. Supported intents: base motion (drive forward/back, turn, stop), arm poses (wave, raise, reach, home), camera (zoom in/out, look left/right, overview), stand up, and go to goal. The simulator applies base motion as wheel velocity + steering targets and arm poses as joint-position targets on the 26-DoF articulation.

5.2 Auto-following camera

To remove the burden of manual 3-D navigation (especially on a trackpad), the viewport camera is recomputed every frame to track R1’s live position, with operator-adjustable distance, height, and orbit angle driven from the same chat interface.

5.3 Containment & safety

Because the imported CAD is visual-only (no colliders), the robot originally passed through walls. A collider “safety fence” (four 3 m walls) was added around the KUKA cell, backed by a software runaway-stop that zeroes the wheels if the robot ever exits the cell bounds. Verified: commanded to drive at a wall, R1 halts at the boundary (x ≈ −4.4 m) instead of crossing.

5.4 Stand-up self-recovery

A tall robot on a three-wheel base can topple during aggressive maneuvers. The clean upright pose is captured at start-up; a stand up command (button + text) resets R1 to that pose with motion and arms zeroed — instant recovery. Driving speed was also softened to reduce tipping.

5.5 Autonomous navigation — the core result

On command, the simulator spawns a random goal marker inside the cell and engages a closed-loop controller: each frame it measures R1’s pose, computes the bearing to the goal, and commands steering + wheel velocity, halting within the 0.8 m tolerance.

Challenge: the steering joints are hard-limited to ±90° in the URDF, so R1 cannot point at goals behind it — naive control made it orbit unreachable targets at ~2.5 m.
Solution (omnidirectional trick): combine the ±90° steering cone with forward or reverse wheels. For a goal behind the robot, steer to the mirror angle (into the cone) and drive backward. This makes R1 effectively holonomic without altering the robot model.

Verified on a goal directly behind R1 (bearing +2.17 rad): distance converged monotonically 4.74 m → 0.80 m and the goal was reached, using reverse drive throughout.

7. Verified Results

  • Teleoperation: base, arms, and camera all respond to chat commands (confirmed via joint-target & pose logs).
  • Autonomous navigation: goals reached to 0.80 m in all directions, including behind the robot via reverse drive.
  • Containment: robot halts at the cell boundary (x ≈ −4.4 m) instead of passing through.
  • Self-recovery: stand up restores the upright pose on demand.
  • Footprint: entire system runs within the 16 GB GPU alongside the RTX viewport.

cd C:\Users\aimat\Desktop\humanoid\IsaacLab
.\isaaclab.bat -p C:\Users\aimat\Desktop\humanoid\r1_chat_sim.py

# 2) start the chat UI (second terminal)
conda activate env_isaaclab
python C:\Users\aimat\Desktop\humanoid\r1_chat_ui.py
